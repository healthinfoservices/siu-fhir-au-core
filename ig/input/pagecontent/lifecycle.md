Every linked FHIR example was generated by running the sample message through the service, so the examples are exactly what it stores.
All people, organisations and identifiers are fictitious; IHI, HPI-I and Medicare numbers are synthetic.


[Appointment FIL2002](Appointment-appointment-fil2002.html) takes its times from AIS-4 + AIS-7/8, in the default time zone (Australia/Brisbane) because AIS-4 has no offset.
Facility `SATELLITE` isn't on the server, so the service created placeholder [Organization SATELLITE](Organization-organization-satellite.html) (tagged `placeholder`) for [Location Physio Room 1](Location-location-satellite-opd-physio1.html), which therefore has no address.
[Patient 900002](Patient-patient-900002.html) has no Indigenous status or language because PID-10 and PID-15 are empty.

* [Patient 900003](Patient-patient-900003.html): no family name, birth date or sex in PID, so `gender` is `unknown`, `birthDate` and an extra name carry data-absent-reason, and the IHI (which fails the Luhn check) is dropped.
* AIP-3 has no family name, so no Practitioner is created: [Appointment FIL2003](Appointment-appointment-fil2003.html) has a display-only participant "ANON".
* The message is still accepted (`AA`) with warnings in the service log.
